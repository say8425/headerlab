# HeaderLab — 팝업 디자인 시스템화 (Tailwind + shadcn + lucide)

2026-08-07

## 왜

소유자의 지적 두 문장이 이 작업의 전부다: **"디자인 시스템화가 안 되었다"**, 그리고
**"미묘하게 유려하지 못하다"**. 두 번째가 첫 번째의 증상이다.

구체적으로 무엇이 덜 유려한지는 네 가지로 좁혔고, 소유자가 넷 모두를 지목했다.

1. **타이포.** `HEADERLAB` / `SITES` / `REQUEST TYPES` 가 전부 자간 벌린 대문자다. 호스트명과
   헤더 이름은 모노스페이스, 나머지는 산세리프. **위계가 크기·무게가 아니라 서체에서 나온다.**
2. **컨트롤 모양이 제각각.** REQ/RES 는 알약, `set`/`remove` 는 테두리 박스, Grant 는 꽉 찬
   버튼, 삭제는 맨 글자 `×` — 한 줄에 버튼 언어가 넷이다. 모서리 반지름도 제각각.
3. **아이콘이 거의 없다.** 로고 세 줄과 체크박스뿐. 삭제는 `×` 문자, 상태는 색 점, 도움말은
   `?` 문자.
4. **여백·밀도가 불균등.** 카드 사이, 레일 섹션 사이, 패널 안쪽 패딩이 모두 달라 수직 리듬이
   없고, 오른쪽 패널 아래가 크게 비어 보인다.

Tailwind·shadcn·Radix·Lucide 는 **이미 설치되어 있으나 죽어 있다.** CLAUDE.md 의 "Known gaps"
가 그렇게 적고 있다. 실제 원인은 하나였다: `entrypoints/popup/style.css` 에
`@import "tailwindcss"` 가 없어서 Vite 플러그인이 물려 있어도 아무것도 방출되지 않았다.
`components.json` 은 이미 `radix-nova` 스타일 · `lucide` 아이콘 · `cssVariables: true` 로
잡혀 있다. 배선은 되어 있고 스위치만 꺼져 있었다.

## 무엇을 하지 않는가

- **정보 구조는 바꾸지 않는다.** 224px 범위 레일 + 규칙 패널이라는 구조와 그 근거는 유지한다.
- **동작은 바꾸지 않는다.** `lib/` 의 순수 계층, `compile()`, 진단, 권한 흐름은 손대지 않는다.
  이 작업은 `components/` 와 `entrypoints/popup/` 안에서 끝난다.
- **새 의존성 없음.** shadcn 컴포넌트는 커밋되는 소스 파일이고, 필요한 Radix primitive
  (Checkbox·Tooltip·Label·Separator·Switch·Slot) 는 설치된 `radix-ui@1.6.7` 에 전부 있다.
  확인함.
- 다크 테마 토글, 프로필 UI, 정규식 UI 는 여전히 만들지 않는다.

## 시각 방향 — "Tight instrument"

세 방향(절제형 / 구조형 / 밀도형)을 그려 비교한 뒤, 소유자가 **"C의 조밀함이 좋은데 감각은
A가 좋다"** 고 판단했다. 그 둘을 두 가지 배합으로 합성해 다시 비교했고 **E · Tight instrument**
가 선택됐다.

참조 시안: `docs/design/2026-08-07-popup-tight-instrument.html` — 평상 상태와 과밀 상태
(사이트 8 · 규칙 10)를 함께 담고 있다. **구현은 이 파일을 기준으로 한다.**

성질:

- **밀도는 C.** 사이트 행 48px, 규칙 행 52px 고정. 한 화면에 규칙 10개. 타입 스케일
  11/12/14/24, 위계는 크기가 아니라 무게와 색이 만든다.
- **감각은 A.** 표면은 테두리가 아니라 톤으로 나뉜다. 버튼은 한 계열 세 톤(solid / subtle /
  ghost)이고 모양이 아니라 무게와 채움으로 구분한다. 알약(999px)은 **스위치 트랙 전용**이다.
  반지름 사다리 4 / 6 / 8 / 10 을 명시해 중첩된 모서리가 단계적으로 줄어든다.
- **모노스페이스는 사용자가 실제로 타이핑하는 값에만** — 호스트명과 헤더 값. 헤더 이름,
  리소스 타입, 섹션 라벨은 산세리프. 그 구분 하나로 "All sites" 행이 사이트가 아님이 읽힌다.
- **대문자 없음.** 문장 케이스. 유일한 예외는 REQ/RES 로, 이건 장식이 아니라 실제 약어다.
- 4px 그리드와 정수 line-height 램프(11→14, 12→16, 14→18, 24→28).

## 토큰 레이어

`entrypoints/popup/style.css` 가 Tailwind 진입점이 된다. `public/theme.js` 는 그대로 두고
(파싱 시점에 `.dark` 를 붙이는 MV3 제약은 변하지 않았다) 클래스 기반 다크 변형만 선언한다.

```css
@import "tailwindcss";
@custom-variant dark (&:is(.dark *));
```

**어휘는 shadcn 표준 하나로 통일한다.** 지금의 `--hl-*` 24개는 사라지고, shadcn 컴포넌트가
기대하는 이름을 쓴다: `--background --foreground --card --card-foreground --muted
--muted-foreground --border --input --ring --primary --primary-foreground --destructive
--radius`.

이 제품에만 있는 것은 같은 방식으로 확장한다:

| 토큰 | 뜻 |
|---|---|
| `--rail --rail-foreground --rail-border` | 레일은 패널과 **다른 재료**다 |
| `--live` | 적용 중 |
| `--pending --pending-bg` | 권한 대기 |
| `--destructive-bg` | 오류 배경 |
| `--req --req-bg` / `--res --res-bg` | 요청 / 응답 |

두 가지를 잃지 않고 옮긴다.

- **레일과 패널의 재료 순서는 다크에서 뒤집힌다.** 라이트에서 레일이 더 어둡고 패널이 밝은
  작업면, 다크에서 레일이 더 밝게 떠 있고 패널이 진짜 검정으로 물러난다. shadcn 기본값에는
  이 개념이 없어 `--rail-*` 을 따로 둔다. 그대로 가져오면 다크에서 "창에 구멍이 뚫린" 모양이
  된다.
- **다크 팔레트는 라이트에서 파생하지 않는다.** 두 블록 다 손으로 맞춘 값이고, 그래서 대비
  가드가 양쪽을 각각 검사한다.

`@theme inline` 으로 위 토큰을 Tailwind 유틸리티에 노출한다.

## 시안 검증이 찾아낸 것 — 구현이 반복하면 안 되는 결함

시안 5개(A/B/C/D/E)에 각각 검증 에이전트를 붙였다. 그 결과가 이 절이다.

### 조용한 클리핑 — 5개 중 5개가 실패했다

전부 고정 높이 + `overflow: hidden` 이었다. 사이트나 규칙이 하나 늘면 **스크롤바도 표시도 없이
사라졌다.** 한 시안은 Grant 버튼이 그것을 위해 마련한 바로 그 띠에 7px 잘렸고, 다른 시안은
규칙을 하나 지우면 남은 규칙이 전부 23.5px 커졌다.

따라서:

- 사이트 목록과 규칙 목록은 **진짜 스크롤 컨테이너**다 — `overflow-y: auto` 와, 실제로 줄어들 수
  있도록 flex 체인 전체에 `min-height: 0`.
- **행 높이는 고정이다.** 사이트 48px, 규칙 52px. 형제가 늘거나 줄어도 행 높이는 변하지 않는다.
  목록에 `flex-grow` 나 `space-between` 을 쓰지 않는다.
- 목록 위아래의 섹션(브랜드, 카운트, Active 스위치, Request types, 패널 헤더)은 **좌표가 고정**
  이다. 평상 상태와 과밀 상태에서 같은 픽셀에 있어야 한다.

### 스크롤바가 보인다고 가정할 수 없다

E 의 주석은 `::-webkit-scrollbar` 로 스타일을 주면 Chromium 이 오버레이 스크롤바에서 빠진다고
주장했다. 여기서는 **대조 실험으로 반증됐다** 고 적었다: 12px 폭에 빨간 썸을 준 상자가
`offsetWidth − clientWidth === 0` 이고 정지 상태에서 아무것도 그리지 않았다.

> **2026-08-09 정정 (Task 10).** 그 반증은 headless 에서만 잰 것이었고, 이 문단은 그 조건을
> 적지 않아 일반 사실로 읽혔다. 2×2 로 다시 재니 `::-webkit-scrollbar` 단독은 headless 에서
> 0px, **headed 에서 8px** 를 예약한다 — 옛 결론은 틀린 게 아니라 좁았고, 사용자가 있는
> 브라우저에서는 거짓이다. 전체 표와 재현 스크립트는
> `docs/research/2026-08-09-headless-vs-headed-scrollbar-gutter.md` 에 있다.
> 아래 결론(잘린 행이 신호다)은 그대로 서지만, 근거가 "스크롤바가 안 보인다" 에서
> "스크롤바가 보이는지는 모드와 OS 설정에 달렸고 잘린 행은 그것과 무관하다" 로 바뀐다.
> 구현은 `scroll-list` 에서 거터와 스크롤바 스타일을 **둘 다** 켠다. 그 조합만이 양쪽
> 모드에서 8px 로 같기 때문이다.

그러므로 **"더 있다"를 말하는 것은 스크롤바가 아니라 잘린 행이다.** 목록의 **최대** 높이를 행
높이의 정수배가 아니게 잡아서, 넘칠 때 가장자리 행이 중간에서 잘리게 한다. 그 잘린 행이 신호이고
어떤 스크롤바 설정에서도 살아남는다.

이것과 아래 결함 2의 "내용만큼 자란다"는 충돌하지 않는다. 셋을 분리해서 읽어야 한다:

| | 규칙 |
|---|---|
| **행** 높이 | 항상 고정 (사이트 48px, 규칙 52px). 형제 수와 무관. |
| **목록** 높이 | 내용만큼 자라되 `max-height` 에서 멈춘다. 안 넘치면 스크롤도 잘린 행도 없다. |
| **max-height** 값 | 행 높이의 정수배가 **아니게** 잡는다. 넘치는 순간에만 잘린 행이 나타난다. |

`scrollbar-gutter: stable` 로 자리는 예약하되, 그것이 보일 것이라고 기대하지 않는다.

### E 자신의 결함 셋

1. **거터가 형제와 어긋난다.** `scrollbar-gutter: stable` 은 스크롤 목록의 콘텐츠 박스만 8px
   깎는다. 그 위 "All sites" 행과 아래 섹션은 8px 더 넓게 끝나서, 두 상태 모두에서 영구적으로
   보이는 어긋남이 생긴다. 거터 예약은 옳다 — 빠진 것은 형제도 같은 8px 들여쓰는 일이다.
2. **평상 상태 레일에 72px(12.5%) 구멍.** 사이트 목록이 `flex: 0 0 176px` 하드 캡이라 사이트가
   2개일 때 뷰포트 안 40px + "Add a site" 와 "Request types" 사이 54px 이 빈다. 사이트 0~1개면
   최대 176px 까지 자란다. 목록은 **내용만큼 자라되 최대치에서 멈추는** 형태여야 한다
   (`max-height` + `flex: 0 1 auto`), 하드 캡이 아니다.
3. **`text-overflow: ellipsis` 는 flex 컨테이너에서 먹지 않는다.** E 의 첫 판은 긴 호스트명을
   `a-very-long-subdomain.` 으로 하드 클립했다 — 뒤에 점이 붙은 채로 잘려 *다른 호스트명처럼*
   읽히는 값이다. 미관이 아니라 정확성 문제다. 생략은 flex 자식이 아니라 그 안의 블록 요소에
   걸고, `min-width: 0` 을 체인에 넣는다.

## 가드

### `tests/unit/contrast.test.ts` — 옮기고, 넓힌다

읽는 이름이 `--hl-ink` → `--foreground` 등으로 바뀐다. **검사하는 쌍의 목록과 4.5:1 기준,
그리고 두 테마를 각각 검사한다는 성질은 손대지 않는다.** 가드의 주제가 살아 있으므로 테스트는
죽는 게 아니라 이동한다.

**추가**: 상호작용 컨트롤의 경계에 3:1 검사를 넣는다(WCAG 1.4.11). 점선 "add" 슬롯과 체크박스
테두리처럼 **경계선이 그것을 컨트롤로 식별시키는 유일한 단서**인 경우다. 지금 이 검사는
존재하지 않고, 시안 5개 중 5개가 여기서 걸렸다. 유일하게 허용되는 예외는 스위치의 OFF 트랙으로,
그건 단어가 아니라 형태다.

### e2e 레이아웃 가드 — 앵커를 계약으로 옮긴다

현재 두 가드가 `.hl-readout` `.hl-pausebar` `.hl-allsites` `.hl-allsitesstate` `.hl-dom`
`.hl-addfield` `.hl-railsec-types` `.hl-types` 8개를 클래스로 짚는다. Tailwind 로 가면 이 클래스는
사라진다. **`data-testid` 로 옮긴다** — 클래스는 스타일이고 testid 는 계약이다.

### 새 e2e 가드 — 과밀 상태

사이트 8개 · 규칙 10개를 심고:

- 사이트 목록과 규칙 목록만 스크롤되고,
- 브랜드 · 카운트 · Active 스위치 · Request types · 패널 헤더의 좌표가 평상 상태와 **동일**하며,
- 스크롤 컨테이너 밖 어떤 노드도 `scrollHeight > clientHeight` 가 아니고,
- 대기 상태 사이트 행의 Grant 버튼이 잘리지 않는다.

시안 5개 중 5개가 정확히 이것에 실패했으므로 코드로 박는다. 이 가드는 **3단계에서 빨간 상태로
들어간다** — 현재 UI 가 실제로 잘리기 때문이다. 4단계가 끝나면 초록이 된다.

### 그대로 두는 것

`bundle.test.ts`(네트워크 프리미티브), `manifest.test.ts`(권한), `purity.test.ts`, 와이어를
증명하는 e2e 2개는 이 작업과 무관하고 손대지 않는다. Tailwind 는 CSS 만 방출하므로 번들 가드에
영향이 없다 — 단계 1 이후 확인한다.

## 순서

각 단계가 독립적으로 초록이고, 매 단계 `npm run screenshots` 로 픽셀 diff 를 남긴다. 그것이
"유려한가"라는 주관적 목표를 객관적으로 확인할 유일한 수단이다.

1. **Tailwind 켜기 + 토큰 레이어 + `contrast.test` 이관.** 화면은 거의 변하지 않는다. 가드는
   한 번도 어두워지지 않는다. 번들에 네트워크 프리미티브가 안 생겼는지 확인.
2. **e2e 앵커를 `data-testid` 로 이동.** 순수 리팩터, 시각 변화 0.
3. **shadcn 컴포넌트 받기 + 과밀 e2e 가드 추가.** 새 가드는 빨강으로 들어간다 — 고쳐야 할
   결함이 실재함을 먼저 증명한다.
4. **컴포넌트 교체**, 한 파일씩: `TypeChecklist` → `SiteRow` → `AddSiteField` → `RuleCard` →
   `RulePanel` → `ScopeRail`. 각 파일마다 `npm run check` + e2e + 스크린샷.
5. **정리.** `HelpTip` 제거, 옛 CSS 삭제, 스크린샷 갱신, CLAUDE.md 의 "Known gaps" 에서 dead
   code 항목 제거 및 디자인 시스템 절 추가.

## 열린 위험

- **번들 크기.** Tailwind 를 켜면 CSS 가 늘어난다. 현재 팝업 CSS 는 13.72kB. 단계 1 이후 실측해
  기록한다. 늘어난다고 되돌릴 이유는 아니지만, 얼마나인지는 알고 있어야 한다.
- **`radix-nova` 스타일의 기본 색이 이 제품의 상태색과 충돌할 수 있다.** shadcn 이 받아오는
  컴포넌트가 `--primary` 를 쓰는데 이 제품의 "적용 중"은 `--live` 다. 받은 소스를 그대로 두지
  말고 이 팔레트에 맞춰 읽는지 단계 3에서 확인한다.
- **긴 호스트명.** 224px 레일에서 `staging.example.com` 이 여유 3px 로 들어간다. 실제로 쓰이는
  가장 긴 호스트를 재보지 않았다. 생략이 정확히 동작하는지가 그래서 더 중요하다.
- **오버레이 스크롤바는 OS 설정에 따라 달라진다.** macOS "스크롤 막대 표시" 설정이 항상 표시로
  되어 있으면 8px 이 실제로 자리를 차지한다. 거터를 예약하는 이유가 그것이고, 두 설정 모두에서
  레이아웃이 같아야 한다.
